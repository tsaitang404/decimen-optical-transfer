# 接收

打开 `/receive/`，点**启动摄像头**，对准发送端的码。没有配对：接收端会在传输中途锁定到任何一条 Decimen 流，自己判断来的是文件还是文本，发送端重启也会干净地重来。

让摄像头画面填满码，把手机靠在什么东西上——手抖导致的自动对焦反复是头号吞吐量杀手。在支持连续自动对焦的摄像头（通常 Android 有）上会自动启用。

进度统计的是**已收集帧数**，不是已解块数——喷泉解码的求解级联集中在后段，所以进度条按帧率估算，只有确认完成的传输才到 100%。

## 落地时

- 文件在任何内容被提供之前先对照其 SHA-256 校验。
- 图片、视频、音频内联预览——视频在页面里播放（绝不自动播放），其他文件只有**保存**链接。
- **接收另一个文件** 重新加载出一个全新的接收端。
- **清除 Decimen 缓存** 把收到的字节从浏览器存储里清掉——见[隐私](privacy.zh-CN.md)。
- 文本片段带**复制**按钮出现，只存在到标签页关闭。

**实时诊断**（采集/解码 fps、有效吞吐、帧数、K）在传输中可折叠，结束后变成**传输摘要**。

## 接收设置

摄像头运行时就实时应用；拒绝实时重配的设备（iOS，有时）会保留当前流并如实告知。摄像头报告达不到的帧率会置灰。

| 设置 | 默认 | 说明 |
|---|---|---|
| 采集宽度 | 1280 | 1920 浪费解码时间；960 帮助弱 CPU |
| 采集 fps | 60 | iOS 除非要求精确值否则给 30——应用已处理 |
| 解码 worker | 2 | 每个 worker 一个 WASM 解码器；繁忙的 worker 丢帧，喷泉码吸收 |
