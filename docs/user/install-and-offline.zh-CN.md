# 安装与离线

三种形态，都从同一份源码构建。三种形态的构建产物都附加在每次[发布](../../../../releases)上。

| | 是什么 | 需要服务器？ | 离线 |
|---|---|---|---|
| **托管站点** | 三个页面加一个 service worker——在 [decimen.app](https://decimen.app/) 在线 | 需要，任意静态托管 | 首次访问后 |
| **`decimen-sender.html`** | 单文件，约 55 KB | 不需要 | 始终 |
| **`decimen-receiver.html`** | 单文件，约 1.3 MB | 见注意事项 | 始终 |

## 托管站点：安装与离线

站点预缓存一切，包括解码 wasm——加载一次，断网也能用。任何页面都会做到；从分享链接直接落到 `/receive/` 也会缓存整个应用。

安装以获得全屏应用体验：

- **Android** — Chrome 从菜单里提供 *安装应用*（真 manifest、正规图标）。
- **iOS** — 分享 → **添加到主屏幕**。

这是手机上该用的形态：它保持真正的 `https://` 源，这正是摄像头想要的。

## 独立文件

`npm run build:standalone` 生成两个页面上没有任何外部引用的文件——没有 script src、没有样式表、没有 fetch。接收端把 940 KB 的解码 wasm 作为 `data:` URI 携带，这就是它 1.3 MB 的原因。用邮件发给别人，丢进 U 盘里。

**接收端唯一的注意事项：** 从 `file://` 打开时，页面获得的是不透明源。桌面 Chrome 和 Firefox 通常会提示授予摄像头并正常工作；**iOS Safari 和 Android Chrome 不会把摄像头给本地文件。** 由于接收端通常是手机，请用任何方式通过 http(s) 伺服这个文件——或者改用托管站点的离线模式。发送端没有这个问题，它从任何地方的 `file://` 都能工作。

## 演示模式

```bash
npm run demo    # 发送端锁定为两个内置图片
```

没有文件选择器，没有文本框——用于一台无人值守摆在大众面前的发送机。这只是带 `VITE_DEMO=1` 的开发服务器，不是加固的信息亭：任何有键盘的人都有 devtools。

## 为什么开发服务器只支持 https

接收端使用 `getUserMedia`，而浏览器会在不安全源上完全移除这个 API——你的手机通过普通 http 访问开发服务器时没有摄像头，就是这样（`localhost` 豁免；但你的手机不是 localhost）。开发服务器自带自签名证书：点一次警告（iOS 上"显示详情 → 访问此网站"，其他地方"高级 → 继续"），页面就成为安全上下文，摄像头就能用了。
