# 故障排查

## "没动静？"

如果摄像头跑了一阵子一个帧都没解出来，预览上方会出现一个小提示条，问的正是这个问题。**帮助**打开提示；**忽略**让它消停（如果仍然没动静它稍后会再出现——点按钮不会让帧自己冒出来）。

修复在**发送端**，这是不直观的部分。按顺序：

1. 在发送端打开传输设置，把**字节/帧降到 1465**。默认的 2953 字节是为近距离手机对手机调优的，在一臂之遥的普通显示器上恰好会失败。
2. 还不行？把发送端**发送 fps 降到 24**。
3. 让摄像头的画面填满码，把手机靠在什么东西上——手抖导致的自动对焦反复是常见元凶。
4. 把发送屏幕的亮度调到最高。

## 摄像头问题

- **权限被拒** — 仔细点浏览器的权限提示；如果不小心点到了"阻止"，为站点允许摄像头，再点**启动摄像头**（无需刷新）。
- **"摄像头需要安全上下文"** — 页面正通过普通 http 伺服。浏览器会在不安全源上移除摄像头 API；改用 https 伺服（开发服务器已经是了，自签名），或者用 [decimen.app](https://decimen.app/)。
- **独立接收文件** — 从 `file://` 打开 `decimen-receiver.html` 在 iOS 或 Android 上拿不到摄像头。见[安装与离线](install-and-offline.zh-CN.md)。

## 传输慢

见[发送](sending.zh-CN.md)里的调优表——字节/帧和发送 fps 是两个真正重要的杠杆。
